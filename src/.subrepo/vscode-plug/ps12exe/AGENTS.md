# AGENTS.md — ps12exe VS Code extension

This directory is the `steve02081504.ps12exe` extension (packaged from `src/.subrepo/vscode-plug/ps12exe` in the main repository). It is also the `defaultFormatter` for PowerShell files in that repository, so the formatter has to leave the repository's own scripts untouched.

## Commands

```powershell
npm install   # once
npm test      # @vscode/test-cli, reuses the local VS Code install
npm run build # package the VSIX and install it into the local VS Code
```

## Formatter invariants

- **Formatting the repository's own scripts must be a byte-for-byte no-op** (after normalizing the BOM): `ps12exe.ps1` and `src/CodeDomCompiler.ps1`. This is enforced by `test/formatting.test.mjs`; keep it passing when touching anything below.
- The extension runs the official PowerShell formatter (`ms-vscode.powershell`, i.e. PowerShell Editor Services → PSScriptAnalyzer `Invoke-Formatter`) first and then applies the preprocessor indentation (`lib/format.mjs#formatPreprocessedText`). The preprocessor indentation builds on the syntax indentation that base produces, so it is only applied when the official formatter ran (`lib/format.mjs#applyPreprocessorFormatting`); when the PowerShell extension is missing the document is left unchanged instead of compounding one level per format.
- `#_!!` and `#_balus` are code once ps12exe strips the marker, but the official formatter sees only comments and flattens their indentation ([PSScriptAnalyzer#2217](https://github.com/PowerShell/PSScriptAnalyzer/issues/2217)). `formatPreprocessedText` passes the pre-format document as `originalText` so `lib/preprocessor.mjs#restoreMarkerIndentation` can put the nesting back (relative to the branch's `#_if`/`#_else` line); `applyPreprocessorFormatting` supplies it. Keep `restoreMarkerIndentation` in sync when changing the pipeline.
- `computeSkipMask` only treats a line as opaque when it is entirely inside a here-string or block comment. A code line that merely carries an inline comment (`catch { <# ignore #> }`) is code and must receive the preprocessor indentation like any other.
- `test/officialFormatter.mjs` emulates that official formatter by mirroring the PSES `powershell.codeFormatting.*` → PSScriptAnalyzer mapping (`LanguageServerSettings.cs`) and running `Invoke-Formatter` through a PowerShell host. When the official extension changes its mapping, update this file.
- The workspace style comes from this extension's `contributes.configurationDefaults` in `package.json`: `[powershell]` defaults to `editor.insertSpaces: false` (tabs), to this extension as `editor.defaultFormatter`, to `editor.wordBasedSuggestions: "off"` (so the `PSEXE`/`PSScript` list is not padded with document words), and `powershell.codeFormatting.newLineAfterOpenBrace` defaults to `false`. Explicit user or workspace settings still win over these defaults, so the repository does not need a `.vscode/settings.json`. `test/officialFormatter.mjs` reads those defaults from `package.json` before applying workspace overrides.

## Notes

- The extension is written as native ES modules (`"type": "module"`, `.mjs` entry and modules), which requires VS Code 1.100+. `npm test` reuses the VS Code installed on this machine; it is located through `@steve02081504/exec`'s `where_command`, and `VSCODE_EXECUTABLE_PATH` can point it at a specific executable. When the install lives on another Windows drive, a junction is created under `.vscode-test/` because `@vscode/test-electron` silently skips tests for cross-drive installs. Without a local install a VS Code copy is downloaded once into `.vscode-test/` and cached.
- `scripts/build.mjs` probes `node_modules` with `npm list --production` (`isDependencyTreeValid`) before calling `vsce package`. `vsce` runs the same command internally to decide which dependencies to ship, and it fails with `ELSPROBLEMS` when the tree was installed by another package manager (e.g. Deno's `deno install` produces a `.deno` store with symlinks). `ensureDependencyTree` runs `npm install` once to repair such a tree and re-checks; `test/build.test.mjs` covers the decision logic and the real tree. Keep the module import-safe: it only runs `main()` when invoked directly via `import.meta.main` (Node >= 24.2, declared in `engines.node`) and must not use top-level `await`, otherwise mocha's CJS `require` of the test file fails.
- Formatter completeness check: each preprocessor block's branch bodies are parsed in one batched call with `[System.Management.Automation.Language.Parser]::ParseInput`; bodies that produce parse errors are never pushed one level deeper. A bare attribute body (`[ArgumentCompleter({…})]`) is retried with a trailing dummy statement so it is not mistaken for an incomplete block. Results are cached per document text.
- The wrapper script sets `$global:LASTEXITCODE = 0` before calling `ps12exe` and ends with `exit $LASTEXITCODE`, because ps12exe reports failures through `$LASTEXITCODE` rather than a terminating error.
- **Find files with `rg --files` (or the Glob tool); never `Get-ChildItem -Recurse`.** The repository vendors `node_modules/` and `.vscode-test/` (a whole VS Code install), so a recursive listing explodes and gets truncated. Filter during the walk (`rg --files -g '!**/node_modules/**'`, or Glob's `path`/`pattern`); `-Exclude` only matches the leaf file name and a `Where-Object` at the end of the pipeline does not stop the traversal. Beware that `rg`/Glob skip dot-directories by default, so this extension's own `src/.subrepo/vscode-plug/ps12exe` needs `--hidden` (or `-uu`) to show up.
- PowerShell is always invoked with `-EncodedCommand` (Base64 UTF-16LE) to avoid every Windows command-line quoting pitfall.
- `-OutputFormat Text` is mandatory, otherwise a redirected host serializes `Write-Host` to stderr as a CLIXML blob.
- New UI strings go through `vscode.l10n.t('…')` and must be added verbatim to every `l10n/bundle.l10n.<locale>.json` (guarded by `test/l10n.test.mjs`). `lib/hover.mjs#HOVER_MESSAGES` is collected by that test like `lib/preprocessor.mjs#MESSAGES`, so its values need bundle entries too.
- Directive hovers (`lib/hover.mjs`) link to the main repository's `docs/README_*` through the explicit `<a id="preprocessing-…">` anchors those files carry (not through headings, whose auto-generated anchors differ by language). Keep `SECTION_ANCHORS` in sync with the `docs/README_*.md` anchors when adding or renaming a directive.
- Preprocessor directive completion (`lib/directives.mjs`) shares its `section` mapping with the hover, so `extension.mjs` builds each hint from `lib/hover.mjs#HOVER_MESSAGES`/`documentationUrl` instead of duplicating text. `lib/directives.mjs#DIRECTIVE_PREFIX_RE` must accept `!` for `#_!!` and stop at the first argument space so `#_pragma ` still reaches the pragma handler. Typing `#_` cannot rely on a trigger character: `_` is a word character, and VS Code routes word-character typing to quick suggestions (off by default in comments, where `#_` lives), while a `#` trigger would pop the list for every ordinary comment. `registerDirectiveSuggest` therefore watches for a typed `_` that lands in a `#_` prefix and calls `editor.action.triggerSuggest`; keep the completion provider's own trigger characters at `.`/` ` for the pragma paths. The provider analyses a probe copy of the document with the directive name under the cursor blanked (`extension.mjs`), then `directiveAvailability` drops `#_else`/`#_endif` unless the innermost open `#_if` allows them — keep that probe in sync if `analyze` changes. `ifConditionPrefixAt` completes the `PSEXE`/`PSScript` keyword after `#_if ` (and must not fire once a trailing comment or extra argument appears); `CONDITION_COMPLETIONS` shares the same `psexe`/`psscript` hover sections. A completion that inserts its own trailing space cannot rely on a trigger character, so `DIRECTIVE_COMPLETIONS`/`CONDITION_COMPLETIONS` declare `followUp` (`suggest` for `#_if`/`#_pragma`, `newline` for the conditions) and `extension.mjs#applyFollowUp` maps it to `editor.action.triggerSuggest` / `editor.action.insertLineAfter` (the latter makes the `#_if` auto-close fire). `registerDirectiveSuggest` also rewrites a full-width `#——`/`#＿` (IME left in Chinese punctuation mode) to `#_`; `MISDIRECTIVE_RE` must only match a whole line of `#` + dash characters so normal comments are untouched. `[powershell]` defaults `editor.wordBasedSuggestions` to `off` in `package.json` so the condition list shows only `PSEXE`/`PSScript`.
- The `#_if` auto-close (`extension.mjs#registerIfAutoClose`) skips `insertEndif` when `lib/preprocessor.mjs#isBalanced` reports every block already closed — a `#_if` that already has its `#_endif` (e.g. the user re-typed Enter at the end of an existing block) must not grow a duplicate. `insertEndif` indents only a blank target line one level and puts the cursor at the end of that line, so the body can be typed immediately. The configuration lookup uses `editorFormattingOptions` so the inserted indent follows the editor's tab/space style.
- `#_pragma` name hover/completion (`lib/pragma.mjs`) reads each parameter's description from the **installed** module, not from a bundled snapshot: it runs PowerShell to load `<ModuleBase>/src/locale/<locale>.ps1`'s `ConsoleHelpData.PrarmsData` for the active locale (same fallback chain as `src/LocaleLoader.ps1`). The result is cached per locale; `clearPragmaCache()` is called after `syncModule` installs or updates the module so the hints follow the new version. When the module is unavailable the hover falls back to the generic `#_pragma` message and completion returns nothing. Nested hashtables (`App`, `Build`, `Build.Core`, …) have no scalar value, so `lookupPragma`/`buildPragmaCandidates` treat them as **groups**: hover and completion describe a group with its direct child keys via the `HOVER_MESSAGES.pragmaGroup` l10n string (`{0}` = comma-separated child names), instead of falling back to the generic message. Keep the locale data shape (`ConsoleHelpData.PrarmsData`) in sync with the main repo; the extension has no copy to update.
- The embedded-exe-source editor (`lib/exeSource.mjs`) must stay a **non-text** custom editor (`openCustomDocument` + `resolveCustomEditor`, i.e. `CustomEditorProvider`). A custom *text* editor (`resolveCustomTextEditor`) makes VS Code build a text model for the resource first, and binary `.exe` files are rejected there with `File seems to be binary and cannot be opened as text`, so the extension callback never runs and the editor shows the "unexpected error" placeholder. `test/extension.test.mjs` pins the interface and opens a real compiled exe through it.
- `#_require` module-name hover (`lib/require.mjs` parses the names, `lib/gallery.mjs` queries them) hits the PowerShell Gallery OData v2 endpoint and parses its Atom XML by hand, because the gallery rejects `$format=json` with HTTP 400 and ships no JSON feed. `gallery.mjs` keeps the `d:`-namespace `fieldValue`/`decodeXml`/`stripHtml` parsing and the per-name cache; query failures are not cached (they retry) and the hover falls back to the generic `#_require` message, while a not-found (null) result is cached. The module separators must stay in sync with `src/ReadScriptFile.ps1`'s `Split(', |;、　')`, and only the first `#` on the line (the trailing comment) truncates the list. The hover renders the description as markdown with hard line breaks: `gallery.mjs#normalizeDescription` keeps the gallery's `&#xD;`/`<br>` line structure (`<li>` becomes `- `), and `hover.mjs#preserveLineBreaks` turns single newlines into markdown hard breaks. The icon is raw `<img … align="left">` HTML with `MarkdownString.supportHtml = true` (a markdown image cannot float), which is what puts the details beside the icon; keep `escapeHtmlAttribute` on the URL.
- Command-usage warnings (`lib/commands.mjs`) are a **separate** analysis from `lib/preprocessor.mjs#analyze` and are merged in `extension.mjs#updateDiagnostics`; do not fold them into `analyze`, whose `diagnostics` are also consumed by `isBalanced`/folding and `test/preprocessor.test.mjs` asserts ps12exe's own scripts produce none. The text scan reuses `computeSkipMask` and treats `#_!!` lines as code. `lib/ps2exe.mjs#convertPs2exeInvocation` rewrites a whole PS2EXE invocation (command name + parameters) to the ps12exe object API; its mapping must stay in sync with `src/.subrepo/PS2EXE2ps12exe/PS2EXE2ps12exe.psm1#Invoke-ps2exe` (`-noConsole` → `App.Windowed`, `-title` → `Resources.Title`, `x86/x64/ARM` → `Build.Platform`, `-Core`/`-TargetOS`/`-SelfContained`… → `Build.Target`/`Build.Core.*`, `-Quiet` → `-Quiet`, …), and it returns `null` (no rewrite) for splatting, unknown/unsupported parameters (`embedFiles`) and multi-line calls rather than guessing. Module-management warnings (`gmo`/`ipmo`/`inmo` and the full cmdlet names) only fire in files that contain a `#_…` preprocessor directive, and only for aliases that `lib/aliases.mjs#loadAliasMap` (one cached PowerShell probe, `currentAliasMap()` fallback) confirms still resolve to `Get-Module`/`Import-Module`/`Install-Module`; an install line matching the `#_require` bootstrap shape gets a whole-line `#_require <module>` rewrite (`commands.mjs#requireFixForLine`). Because those warnings (and the `#_require` fix) only make sense for the compiled product, they are skipped on lines that never enter the exe — `commands.mjs` masks them with `lib/preprocessor.mjs#exeLineMask`, so a `#_if PSScript` branch (and the script side of any block) gets no suggestion, while PS2EXE-call warnings stay branch-independent. Requiring the deprecated module (`#_require PS2EXE`, case-insensitive) is its own `ps2exe-require` diagnostic: `lib/require.mjs#requireModules` lists every module token on the line, and each `PS2EXE` one gets a token-range `ps12exe` replacement (same exe-only suppression); the module separators live in `require.mjs` and must stay in sync with `src/ReadScriptFile.ps1`'s `Split(', |;、　')`. `# use_ps12exe:ignore` (on the line above or trailing) suppresses every ps12exe diagnostic through `commands.mjs#computeIgnoredMask`, and `extension.mjs#codeActionProvider` offers the quick fixes (migrate the PS2EXE call, rewrite the module install, insert the marker). `COMMAND_MESSAGES` values are l10n keys collected by `test/l10n.test.mjs` alongside `MESSAGES`/`HOVER_MESSAGES`.
- `#_pragma Resources.Icon` icon support lives in `lib/icon.mjs` plus the icon-aware `lib/definition.mjs#resolveDirectivePath`, which now returns `{ file, kind, index, start, end }` and strips the desktop.ini-style `,<index>` suffix from the resolved `file` (that is what makes go-to-definition work for `shell32.dll,-16`); its `start`/`end` still span the whole value including the index. Hover previews read renderable images (`png/jpg/jpeg/gif/bmp/webp`) straight into a `data:` URI, and hand `.ico`/`.tif`/PE containers to PowerShell (`System.Drawing` → PNG base64) via `buildProbeScript`. The container extensions and extraction order (`PrivateExtractIcons` at 256px, then `ExtractIconEx` fallback, explicit index on a non-image extension ⇒ extract) must stay in sync with `src/InitCompileThings.ps1` (`$iconContainerExtensions` and the `,<index>` convention). Previews are cached per file mtime + index, and the probe returns null (no hover) instead of throwing when extraction fails.
- The extension bundles an Agent Skill at `skills/ps12exe/SKILL.md`, contributed through `package.json#contributes.chatSkills`. That file is **generated** (and gitignored): `scripts/sync-skill.mjs` copies it from the main repository's `src/AgentSkill/SKILL.md`, which is the single source also installed by the ps12exe module into `~/.agents/skills`. `pretest` and `scripts/build.mjs` run the sync before tests/packaging, so edit the main repo file, never the generated copy. VS Code 1.109+ loads extension skills; `engines.vscode` stays at `^1.100.0`, so older versions just ignore the contribution. `test/skill.test.mjs` guards that the contributed path resolves inside the extension, the file exists, the frontmatter `name` is lowercase kebab-case and equals the parent folder name, and the `description` is present and ≤ 1024 characters. Keep the skill free of parameter tables and of any repository-checkout assumption: it tells the agent to install `ps12exe`/`PS2EXE2ps12exe`, to run `ps12exe -help`, to read the installed `PS2EXE2ps12exe` module's `Invoke-ps2exe`, and to open the installed ps12exe module's `README.md`, so it stays short and cannot drift from the compiler or the compatibility layer.
