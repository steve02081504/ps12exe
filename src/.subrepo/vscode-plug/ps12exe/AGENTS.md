# AGENTS.md — ps12exe VS Code extension

This directory is the `steve02081504.ps12exe` extension (packaged from `src/.subrepo/vscode-plug/ps12exe` in the main repository). It is also the `defaultFormatter` for PowerShell files in that repository, so the formatter has to leave the repository's own scripts untouched.

## Commands

```powershell
npm install   # once
npm test      # @vscode/test-cli, reuses the local VS Code install
npm run build # package the VSIX and install it into the local VS Code
```

## Formatter invariants

- **Formatting the repository's own scripts must be a byte-for-byte no-op** (after normalizing the BOM): `ps12exe.ps1` and `src/CodeDomCompiler.ps1`. Enforced by `test/formatting.test.mjs`; keep it passing when touching anything below.
- The extension runs the official PowerShell formatter (`ms-vscode.powershell`, i.e. PowerShell Editor Services → PSScriptAnalyzer `Invoke-Formatter`) and then applies the preprocessor indentation (`lib/format.mjs#formatPreprocessedText`). The preprocessor indentation builds on the base syntax indentation, so it is only applied when the official formatter ran (`lib/format.mjs#applyPreprocessorFormatting`); when the PowerShell extension is missing the document is left unchanged instead of compounding one level per format.
- `#_!!` and `#_balus` are code once ps12exe strips the marker, but the official formatter sees only comments and flattens their indentation ([PSScriptAnalyzer#2217](https://github.com/PowerShell/PSScriptAnalyzer/issues/2217)), so `formatPreprocessedText` passes the pre-format document as `originalText` for `lib/preprocessor.mjs#restoreMarkerIndentation` to put the nesting back (relative to the branch's `#_if`/`#_else` line).
- `computeSkipMask` treats a line as opaque only when it is entirely inside a here-string or block comment; a code line with an inline comment (`catch { <# ignore #> }`) is code and must receive the preprocessor indentation like any other.
- `test/officialFormatter.mjs` emulates the official formatter by mirroring the PSES `powershell.codeFormatting.*` → PSScriptAnalyzer mapping (`LanguageServerSettings.cs`); update it when that mapping changes.
- The workspace style comes from `contributes.configurationDefaults` in `package.json`: `[powershell]` defaults to tabs (`editor.insertSpaces: false`), this extension as `editor.defaultFormatter`, `editor.wordBasedSuggestions: "off"` (so the `PSEXE`/`PSScript` list is not padded with document words) and `powershell.codeFormatting.newLineAfterOpenBrace: false`. Explicit user/workspace settings still win, so the repository needs no `.vscode/settings.json`; `test/officialFormatter.mjs` reads those defaults before applying overrides.

## Notes

- Native ES modules (`"type": "module"`, `.mjs` entry and modules) require VS Code 1.100+. `npm test` reuses the VS Code installed on this machine (located through `@steve02081504/exec`'s `where_command`; `VSCODE_EXECUTABLE_PATH` can point it at a specific executable). A cross-drive install gets a junction under `.vscode-test/` because `@vscode/test-electron` silently skips tests for cross-drive installs; without a local install a VS Code copy is downloaded once and cached.
- `scripts/build.mjs` probes `node_modules` with `npm list --production` (`isDependencyTreeValid`) before `vsce package`, which fails with `ELSPROBLEMS` when the tree was installed by another package manager (e.g. Deno's `.deno` store with symlinks); `ensureDependencyTree` runs `npm install` once to repair it and re-checks. Keep the module import-safe: it runs `main()` only via `import.meta.main` (Node >= 24.2, declared in `engines.node`) and must not use top-level `await`, or mocha's CJS `require` of `test/build.test.mjs` fails.
- Formatter completeness check: each preprocessor block's branch bodies are parsed in one batched `[System.Management.Automation.Language.Parser]::ParseInput` call; bodies with parse errors are never pushed one level deeper, and a bare attribute body (`[ArgumentCompleter({…})]`) is retried with a trailing dummy statement. Cached per document text.
- The wrapper script sets `$global:LASTEXITCODE = 0` before calling `ps12exe` and ends with `exit $LASTEXITCODE`, because ps12exe reports failures through `$LASTEXITCODE` rather than a terminating error.
- **Find files with `rg --files` (or the Glob tool); never `Get-ChildItem -Recurse`.** `node_modules/` and `.vscode-test/` (a whole VS Code install) are vendored, so a recursive listing explodes; filter during the walk (`rg --files -g '!**/node_modules/**'`) since `-Exclude`/a trailing `Where-Object` do not stop the traversal. `rg`/Glob skip dot-directories by default, so this extension's own path needs `--hidden` (or `-uu`).
- PowerShell is always invoked with `-EncodedCommand` (Base64 UTF-16LE) to avoid Windows command-line quoting, and with `-OutputFormat Text` (otherwise a redirected host serializes `Write-Host` to stderr as a CLIXML blob).
- New UI strings go through `vscode.l10n.t('…')` and must be added verbatim to every `l10n/bundle.l10n.<locale>.json` (guarded by `test/l10n.test.mjs`, which also collects `HOVER_MESSAGES`, `MESSAGES` and `COMMAND_MESSAGES`).
- Directive hovers (`lib/hover.mjs`) link to the main repository's `docs/README_*` through the explicit `<a id="preprocessing-…">` anchors those files carry (not through headings, whose auto-generated anchors differ by language); keep `SECTION_ANCHORS` in sync.
- Preprocessor directive completion (`lib/directives.mjs`): `extension.mjs` builds each hint from `lib/hover.mjs#HOVER_MESSAGES`/`documentationUrl`; `DIRECTIVE_PREFIX_RE` must accept `!` for `#_!!` and stop at the first argument space. Typing `#_` cannot rely on a trigger character (`_` is a word character), so `registerDirectiveSuggest` watches for a typed `_` in a `#_` prefix and calls `editor.action.triggerSuggest`, while the provider keeps `.`/` ` triggers for the pragma paths. The provider analyses a probe copy with the directive under the cursor blanked, and `directiveAvailability` drops `#_else`/`#_endif` unless the innermost open `#_if` allows them; `ifConditionPrefixAt` completes the `PSEXE`/`PSScript` keyword after `#_if ` (and must not fire once a trailing comment or extra argument appears); `DIRECTIVE_COMPLETIONS`/`CONDITION_COMPLETIONS` declare `followUp` mapped by `extension.mjs#applyFollowUp`. `registerDirectiveSuggest` also rewrites full-width `#——`/`#＿` (IME in Chinese punctuation mode) to `#_`, and `MISDIRECTIVE_RE` must only match a whole line of `#` + dashes so normal comments are untouched.
- The `#_if` auto-close (`extension.mjs#registerIfAutoClose`) skips `insertEndif` when `lib/preprocessor.mjs#isBalanced` reports every block already closed (a re-typed Enter must not grow a duplicate); `insertEndif` indents only a blank target line one level and puts the cursor at its end so the body can be typed immediately. The indent follows `editorFormattingOptions`.
- `#_pragma` name hover/completion (`lib/pragma.mjs`) reads each parameter's description from the **installed** module's `ConsoleHelpData.PrarmsData` for the active locale (same fallback chain as `src/LocaleLoader.ps1`), cached per locale and cleared by `clearPragmaCache()` after `syncModule` installs or updates the module; when the module is unavailable the hover falls back to the generic message and completion returns nothing. Nested hashtables (`App`, `Build`, `Build.Core`, …) have no scalar value and are treated as **groups** described via the `HOVER_MESSAGES.pragmaGroup` l10n string. Keep the locale data shape in sync with the main repo.
- PowerShell text-lexing helpers live in `lib/tokens.mjs` (`skipString`, `readValueToken`, `isCompleteLine`) and are shared by `lib/commands.mjs`, `lib/cli.mjs` and `lib/ps2exe.mjs`; keep them the single source when another module needs to lex a PowerShell line.
- ps12exe CLI parameter support (`lib/cli.mjs`) reuses the installed-module `PrarmsData`: `scanCliInvocations` masks here-strings/block comments/`#_!!` and parses `ps12exe`/`ps12exe.ps1` invocations so `-App @{ … }` members become dotted paths (`app.windowed`, `build.core.aot`) for `lookupPragma`; hover links to the `console-parameters` README anchor and `analyzeCliUsage` emits `ps12exe-parameter`/`ps12exe-parameter-member` diagnostics (common `[CmdletBinding()]` parameters are always allowed). Only the static `GROUP_PARAMS` (`App`/`Os`/`Build`/`Resources`/`Signing`) members are parsed; add new group parameters there. Keep the data complete or unknown-option false positives appear (`Build.ConstEval` is a real CLI/pragma option).
- The embedded-exe-source editor (`lib/exeSource.mjs`) must stay a **non-text** custom editor (`openCustomDocument` + `resolveCustomEditor`): a custom *text* editor makes VS Code reject binary `.exe` files with "File seems to be binary and cannot be opened as text". `test/extension.test.mjs` pins the interface.
- `#_require` module-name hover (`lib/require.mjs` parses the names, `lib/gallery.mjs` queries them) hits the PowerShell Gallery OData v2 endpoint and parses its Atom XML by hand (the gallery rejects `$format=json` with HTTP 400); query failures are not cached (they retry) while a not-found result is. Keep the module separators in sync with `src/ReadScriptFile.ps1`'s `Split(', |;、　')`; only the first `#` on the line (the trailing comment) truncates. The hover renders markdown with hard line breaks and a raw floating `<img>` icon (`MarkdownString.supportHtml`), with `escapeHtmlAttribute` on the URL.
- Command-usage warnings (`lib/commands.mjs`) are a **separate** analysis from `lib/preprocessor.mjs#analyze`, merged in `extension.mjs#updateDiagnostics`; do not fold them into `analyze`. `lib/ps2exe.mjs#convertPs2exeInvocation` must stay in sync with `src/.subrepo/PS2EXE2ps12exe/PS2EXE2ps12exe.psm1#Invoke-ps2exe` and returns `null` (no rewrite) for splatting, unknown/unsupported parameters (`embedFiles`) and multi-line calls. Module-management warnings only fire in files with a `#_…` directive and for aliases `lib/aliases.mjs#loadAliasMap` confirms; the `#_require` fix and these warnings are suppressed on lines that never enter the exe via `lib/preprocessor.mjs#exeLineMask`. `#_require PS2EXE` is its own `ps2exe-require` diagnostic; `# use_ps12exe:ignore` suppresses all ps12exe diagnostics through `commands.mjs#computeIgnoredMask`, and `extension.mjs#codeActionProvider` offers the quick fixes.
- `#_pragma Resources.Icon` support (`lib/icon.mjs`, `lib/definition.mjs#resolveDirectivePath`) returns `{ file, kind, index, start, end }` and strips the desktop.ini-style `,<index>` suffix from `file` (so go-to-definition works for `shell32.dll,-16`). The container extensions and extraction order (`PrivateExtractIcons` at 256px, then `ExtractIconEx`) must stay in sync with `src/InitCompileThings.ps1`; previews are cached per file mtime + index and the probe returns null (no hover) on failure.
- The extension bundles an Agent Skill at `skills/ps12exe/SKILL.md`, contributed through `package.json#contributes.chatSkills`. That file is **generated** (and gitignored) by `scripts/sync-skill.mjs` from the main repository's `src/AgentSkill/SKILL.md` (the single source also installed into `~/.agents/skills`); edit the main repo file, never the generated copy. `pretest` and `scripts/build.mjs` run the sync before tests/packaging. `test/skill.test.mjs` guards the contributed path, the frontmatter (`name` lowercase kebab-case = parent folder, `description` ≤ 1024 chars). Keep the skill free of parameter tables and checkout assumptions.
